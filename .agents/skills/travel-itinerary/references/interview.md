# ヒアリングの進め方

## 目標: 往復は 3 回まで

1. **決まっていること**を自由に書いてもらう（自由記述は基本的にここだけ）
2. しおりに必要なのに分からないことだけを、**選択肢で**聞く
3. AI の提案をまとめて見せ、**選択肢で**決めてもらう → OK ならそのまましおりを作る

ユーザーが答えるのは「最初の自由記述」と「数回のクリック（または A/B の一文字）」だけにする。

## 基本ルール

- **自由記述の質問を並べない。** 答えの候補が考えられる質問は、すべて選択肢にする。選択肢には必ず「おまかせ」を入れ、おすすめを一番上に置いて「（おすすめ）」と付ける
- **1 回に聞くのは 4 問まで。** 5 問以上になりそうなら、しおりの出来を大きく変えない質問を削り、AI が決めて提案に回す
- **AI が決められることは聞かない。** 夜ごはんのお店、空いている時間の過ごし方、雨天プランを用意する日、持ち物の担当、日程の細かい時刻などは、AI が調べて決め、最後の提案に入れる。気に入らなければユーザーがそこで変えればよい
- すでに分かっていること（最初の自由記述や依頼文に書いてあること）は聞き直さない
- 予約済みのもの（便名・時刻・宿の名前など）は、そのまましおりに載せる。AI が勝手に変えない
- 調べもの（天気・お店・観光スポット・参考ブログ）は**黙って進める**。「〜を調べています。結果がそろったら確認をお願いします」のような予告や、途中経過の報告はしない
- 調べた結果の確認だけのために、ユーザーに一往復させない。確認は最後の提案（ステップ 3）にまとめる

聞き方はエージェントで変える。

- **Claude Code**: `AskUserQuestion` を使う（1 回で最大 4 問、各 2〜4 択。「その他」は自動で付く）
- **Codex / Kiro**: 番号付きの選択肢をメッセージで出し、「1-A, 2-おまかせ」のように短く答えられるようにする。最後に「全部おまかせなら『おまかせ』だけで OK」と添える

## ステップ 1: 決まっていること（自由記述）

> この旅行で、もう決まっていることを教えてください。
> 行き先・日程・メンバー、予約済みの飛行機や船・宿、行きたい場所、予算、集合時刻など、何でも OK です（箇条書きや、予約メールの貼り付けでも大丈夫です）。

- 予約メールなどが貼られた場合は、必要な情報だけを使う。予約番号・電話番号・メールアドレスは、ユーザーが載せたいと言わない限りしおりに入れない
- 持病・けが・アレルギーなどの健康の情報は、ユーザーが書いたときだけ扱う。しおりに載せるかどうかは、ステップ 3 で選択肢で確認する

## ステップ 2: 足りないことを選択肢で聞く（最大 4 問）

しおりを作るのに**必須**なのは、行き先・日程（出発日と帰着日）・メンバーの人数だけ。これが分からなければ最優先で聞く。そのうえで、次の候補から、まだ分からずしおりの出来を大きく変えるものを選んで聞く。

| 候補 | 選択肢の例 |
|------|------------|
| 入れるもの（複数選択） | 天気 / 雨天プラン / 持ち物リスト / 参考ブログ。**全部にチェックを入れた状態をおすすめ**にする |
| 予算（1 人あたり） | おまかせ（目安を出す）（おすすめ） / なるべく安く / 〇万円くらい / 〇万円くらい。金額の候補は、行き先・日数・予約済みの内容から 2 つ出す |
| 旅のペース | ゆったり（おすすめ） / 予定を詰めて色々回る |
| 精算のしかた | 各自で払う / 誰かがまとめて払って割り勘 / 決めていない（しおりに載せない） |

- 交通や宿が決まっていなくても、聞かずに「未定」として進めてよい
- この時点で、Web 検索が使えるなら調べものを始める（ステップ 2 の回答を待つ間に並行して進めてよい）

## ステップ 3: 提案をまとめて見せる → 選択肢で決める

調べた結果と、AI が決めた部分をまとめて見せる。見出しと短い箇条書きだけにし、長い説明はしない。

```
## しおりの内容（案）

決まっていること
- 8/10（月）〜 8/12（水）札幌・小樽、4 人
- 行き: 羽田 8:30 発の飛行機 / 宿: 1 泊目 札幌、2 泊目 小樽

AI からの提案
- 8/10 夜: すすきのでジンギスカン（候補のお店 2 つ）
- 8/11 昼: 白い恋人パーク → 小樽運河 / 夜: 宿の夕食
- 雨天プラン: 8/11（小樽運河の代わりにガラス工房の体験）
- 予算の目安: 1 人 8 万円前後（飛行機・宿・レンタカー込み）
- 持ち物: 基本の持ち物 ＋ 薄手の上着
- 参考ブログ: 5 件 / 天気: 平年の気候（8 月の札幌）

確認したいこと
- メンバーのけがのことを、メモに載せますか？
```

そのあと、選択肢で聞く（Claude Code なら `AskUserQuestion`）:

- **この内容でしおりを作る（おすすめ）**
- 提案の一部を変えたい（どこを変えるか、続けて聞く）
- 提案は使わず、決まっていることだけで作る

「確認したいこと」がある場合は、同じ `AskUserQuestion` の 2 問目として選択肢で聞く（例: 載せる / 載せない）。

- 「作る」を選ばれたら、追加の質問をせずに JSON を書いてしおりを作る
- 「一部を変えたい」の場合は、変えたいところだけを聞き、直したら作る。もう一度全体の確認はしない
- 提案した部分は、しおりの中でも決まっていることのように見せない。たとえば、お店は `note` に「候補」と書き、営業日や予約の要否が分からなければ「要確認」と書く
