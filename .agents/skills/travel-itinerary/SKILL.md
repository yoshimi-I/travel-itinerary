# 旅のしおり作成

ユーザーに質問して旅の情報を集め、メンバーに配れる HTML のしおりを作る。

このファイルがあるディレクトリを `<skill_dir>` と呼ぶ（インストールした場合は `~/.claude/skills/travel-itinerary`・`~/.agents/skills/travel-itinerary`・`~/.kiro/skills/travel-itinerary` のどれか、リポジトリ内なら `.agents/skills/travel-itinerary`）。コマンドを実行するときは、`<skill_dir>` を実際の絶対パスに置き換える。

| ファイル | 用途 |
|----------|------|
| `<skill_dir>/references/interview.md` | 質問の進め方と質問項目 |
| `<skill_dir>/references/schema.md` | しおり JSON の仕様 |
| `<skill_dir>/assets/template.html` | しおりの HTML テンプレート |
| `<skill_dir>/scripts/build.py` | JSON を埋め込んで HTML を出力するスクリプト |

## 手順

### 1. ヒアリング

`references/interview.md` を読み、その手順で進める。**ユーザーとの往復は 3 回まで**にする。

1. 「もう決まっていること」を自由に書いてもらう
2. 足りないことだけを、おすすめ付きの選択肢で聞く（最大 4 問）
3. 調べた結果と AI の提案をまとめて見せ、「この内容で作る（おすすめ）/ 一部を変えたい / 決まっていることだけで作る」から選んでもらう

夜ごはんのお店や空いた時間の過ごし方、雨天プランの日、持ち物の担当など、AI が決められることは聞かずに提案に入れる。手順 2・3 の調べものは、ステップ 2 の回答を待つ間に並行して黙って進め、途中経過は報告しない。

### 2. 天気を調べる（天気を入れる場合）

- **出発日が約 2 週間以内**で、Web 検索が使えるなら、行き先の天気予報を調べる → `weather.source` は `"forecast"`、`checkedAt` に調べた日を書く
- **それ以外**は、その時期の平年の気候（平均気温・雨の多さ）を目安として書く → `weather.source` は `"climate"`。推測で具体的な予報を書かない
- どちらの場合も、`weather.links` に最新の予報を確認できるリンク（tenki.jp、気象庁など。海外なら現地の気象サイト）を入れる
- 気温と季節から、服装のアドバイスを `clothing` と `note` に書く

### 3. 参考ブログを探す（参考ブログを入れる場合）

Web 検索（Claude Code なら `WebSearch` / `WebFetch`）が使えるときだけ行う。使えない場合は、探せなかったことをユーザーに伝えて、このセクションは省略する。

1. 「行き先 ＋ 旅行 ブログ」「行く場所の名前 ＋ ブログ / 体験記」などで検索する。旅全体について 1〜3 件、主な行き先ごとに 1〜2 件、合計 3〜10 件を目安にする
2. 候補は **必ず実際に開いて**、ページが存在すること、内容がその場所の話であることを確かめる。開けなかったもの、広告ばかりのもの、内容が違うものは使わない
3. 新しい記事を優先する（目安は 3 年以内）。個人のブログ・旅行メディア・公式サイトがほどよく混ざるようにする
4. 記事ごとに `articles[]` に書く: タイトル（ページの見出しのまま）、URL（開いたページの URL のまま）、サイト名、種類（`ブログ` / `旅行メディア` / `公式サイト`）、関係する場所（`about`）、1〜2 文の要約（自分の言葉で書き、本文を書き写さない）、確認した日（`checkedAt`）

**URL を推測で作らない。** 検索結果と実際に開いたページで確認できたものだけを載せる。

### 4. JSON を書く

`references/schema.md` を読み、集めた内容を JSON にする。

- 保存先: 今いるディレクトリの `output/<slug>/itinerary.json`（`<slug>` は英小文字とハイフン。例: `2026-08-hokkaido`）。ユーザーが別の場所を指定したら、そちらに保存する
- 必須は `trip`（`title` / `destination` / `startDate` / `endDate`）と `days`
- 選ばれなかったオプションのセクションは書かない（タブが出なくなる）
- 場所には `mapQuery` を付ける（地図のリンクになる）
- 移動・宿に外部リンクがあれば `links` に入れる。ユーザーがくれたリンクに加えて、Web 検索が使えるなら、使う航空会社・船会社・鉄道会社の**運航状況のページ**を探して足してよい（実際に開いて確かめたものだけ）。予約確認ページの URL は、個人情報が含まれることがあるので入れない

### 5. HTML をビルドする

```bash
python3 <skill_dir>/scripts/build.py output/<slug>/itinerary.json output/<slug>/index.html
```

- エラーが出たら、メッセージに従って JSON を直し、もう一度実行する
- **python3 が使えない場合**: `assets/template.html` をコピーし、`/*__ITINERARY_DATA__*/` を JSON で置き換えて `output/<slug>/index.html` に保存する。そのとき JSON 内の `<` はすべて `\u003c` に置き換える（`</script>` で埋め込みが途切れないようにするため）

### 6. 仕上げ

ユーザーに次を伝える:

- 生成したファイルのパス（`output/<slug>/index.html`）と、ブラウザで開けば確認できること
- 配り方:
  - HTML ファイルをそのまま送る（LINE・メールなど）。外部ファイルに依存しないので、受け取った人もそのまま開ける
  - 紙で配るなら、ブラウザで印刷して PDF にする（全タブが順番に印刷される）
  - GitHub Pages などで公開する場合は、URL を知っていれば誰でも見られることに注意する
- 個人情報の注意: 電話番号・予約番号などを入れた場合は、公開しないこと
- 修正したいところがあれば、言ってもらえれば直せること

修正を頼まれたら、`itinerary.json` を直して手順 5 をやり直す。HTML を直接編集しない。

## 守ること

- 決まっていないことを、決まったことのように書かない。AI が提案した予定は、確認のときに提案だと伝える
- 営業時間・料金・予報などは、調べられなかったら「要確認」と書く
- しおりをコミットしない（個人情報が入るため）。今いるディレクトリが git リポジトリなら、`output/` を `.gitignore` に入れるか、ユーザーに確認する

## エージェントごとの補足

- **Claude Code**: ステップ 1 の自由記述以外は、すべて `AskUserQuestion` で聞く（1 回で最大 4 問）。入れるものの選択は `multiSelect: true` にする。調べものは、サブエージェントや複数のツール呼び出しで並行して進めてよい。天気予報と参考ブログは `WebSearch` で探し、`WebFetch` で実際に開いて確かめる
- **Kiro**: 質問は、番号付きの選択肢をメッセージで出して聞く（「1-A, 2-おまかせ」のように短く答えられる形）。Web 検索・Web ページ取得のツールが使えるときは、それで天気予報と参考ブログを調べる。使えないときは、天気予報（平年の気候で代わりにする）と参考ブログ（省略する）について、そのことをユーザーに伝える
- **Codex**: 質問は、番号付きの選択肢をメッセージで出して聞く（「1-A, 2-おまかせ」のように短く答えられる形）。Web 検索が使えない設定のときは、天気予報（平年の気候で代わりにする）と参考ブログ（省略する）について、そのことをユーザーに伝える
